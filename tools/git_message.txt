Fix online joining: candidates inside the description, host keeps the lobby

Joining a friend failed with max connection attempts reached, and the host
then closed the lobby. Two causes, both checked on the director's PC with the
new tools/net_probe.tscn (a hidden host and joiner through the real public
trackers):

1. tracker.openwebtorrent.com passes on only the answer's type and sdp and
   drops our extra ice_candidates list. Tube threw such answers away, so a
   join worked only when the one tracker that keeps the list delivered.
   Now the candidates also go inside the sdp as a=candidate lines
   (addons/tube/tube_tracker.gd sdp_with_candidates) and an answer without
   the list is accepted; tools/webrtc_sdp_probe.tscn showed the WebRTC
   library connects from candidates in the sdp alone.

2. game/net_session.gd left the session on ANY Tube error. After a joiner
   failed, the host's join timeout kicked a peer Tube had already dropped,
   Kick peer failed came back as an error, and the host closed the lobby.
   Only failing to create or join a session ends it now.

Also: join tries 5 s x 6 instead of 2 s x 3, join timeout 10 s, two trackers
that refuse our requests removed, three more added, a tracker's refusal
reason is logged.
